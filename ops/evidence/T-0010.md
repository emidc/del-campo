## Observación externa

La comprobación en el borde no la da ningún test del repositorio: la da Postgres.

```sql
create extension if not exists btree_gist;
create table ensayo_pv (
  policy_id uuid not null,
  vigencia daterange not null,
  exclude using gist (policy_id with =, vigencia with &&)
);
insert into ensayo_pv values ('1111…', daterange('2026-01-01','2026-07-01'));
insert into ensayo_pv values ('1111…', daterange('2026-06-01','2026-12-01'));
```

```text
CREATE EXTENSION
  extname   | extversion
------------+------------
 btree_gist | 1.7
CREATE TABLE
INSERT 0 1
ERROR:  conflicting key value violates exclusion constraint "ensayo_pv_policy_id_vigencia_excl"
DETAIL:  Key (policy_id, vigencia)=(1111…, [2026-06-01,2026-12-01)) conflicts with existing key (policy_id, vigencia)=(1111…, [2026-01-01,2026-07-01)).
```

Un Postgres real rechazó dos intervalos solapados para la misma póliza usando
exactamente la construcción que T-0012 necesita —`EXCLUDE USING gist` con `btree_gist`
para poder igualar el `policy_id` en la misma constraint—. Eso es lo que `D-0045`
sostiene: la invariante vive donde la base la puede hacer cumplir. La tabla de ensayo se
eliminó después de comprobarlo.

La observación se hizo sobre PostgreSQL **16**, no sobre la 17 que fija
`.postgres-version`. `btree_gist` y `EXCLUDE USING gist` existen en ambas y la 17 no
cambió ninguna de las dos, pero esto es evidencia sobre 16 y se lee como tal.
