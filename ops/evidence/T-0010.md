## Observación externa

La comprobación en el borde no la da ningún test del repositorio: la da Postgres.

```sql
create extension if not exists btree_gist;
create table ensayo_pv (
  policy_id uuid not null,
  vigencia daterange not null,
  exclude using gist (policy_id with =, vigencia with &&)
);
insert into ensayo_pv values ('1111…', daterange('2026-01-01','2026-07-01'));
insert into ensayo_pv values ('1111…', daterange('2026-06-01','2026-12-01'));
```

```text
CREATE EXTENSION
  extname   | extversion
------------+------------
 btree_gist | 1.7
CREATE TABLE
INSERT 0 1
ERROR:  conflicting key value violates exclusion constraint "ensayo_pv_policy_id_vigencia_excl"
DETAIL:  Key (policy_id, vigencia)=(1111…, [2026-06-01,2026-12-01)) conflicts with existing key (policy_id, vigencia)=(1111…, [2026-01-01,2026-07-01)).
```

Un Postgres real rechazó dos intervalos solapados para la misma póliza con exactamente la
construcción que T-0012 necesita —`EXCLUDE USING gist` con `btree_gist`, que es lo que
permite igualar el `policy_id` dentro de la misma constraint—. Eso es lo que `D-0045`
sostiene: la invariante vive donde la base la puede hacer cumplir, y un DSL que no la
exprese la dejaría fuera del archivo que dice ser el schema. La tabla de ensayo se
eliminó después de comprobarlo.

**Esto corrió sobre PostgreSQL 16, no sobre la 17 que fija el repositorio.** Sobre la 17
de la máquina de desarrollo sólo se comprobó que `btree_gist` se crea.

## Qué NO se verificó

1. **El `EXCLUDE USING gist` no se ejercitó sobre PostgreSQL 17.** `btree_gist` y las
   constraints de exclusión existen en ambas mayores y la 17 no las cambió, pero la
   observación externa de arriba es evidencia sobre 16 y se lee como tal. Quien quiera
   cerrarlo lo cierra con el primer test negativo de T-0012, que corre sobre 17.
2. **El procedimiento de instalación no se probó en una máquina limpia.** Corrió en un
   Mac que ya tenía Homebrew, Node y pnpm. Lo que dice el documento sobre una máquina sin
   nada está escrito contra la documentación de Homebrew, no observado.
3. **CI no corrió.** El workflow no se tocó —está en el `## Non-scope`— y sigue sin
   servicio de Postgres: lo declara T-0012, y tocarlo requiere aprobación humana por
   R-13. Que `pnpm check` pase local no es el veredicto. → R-17
4. **`pnpm check` sigue sin incluir typecheck, lint ni test**, por diseño. La consecuencia
   conocida es que entre esta tarea y T-0012 nada obliga a que sigan pasando, y la primera
   corrida de `pnpm lint` acá muestra que una configuración sin ejecutar no es una
   configuración que funcione. El cableado es del `## Outcome` de T-0012.
5. **`migrate` nunca corrió sobre una migración real en la máquina de desarrollo**: el
   directorio está vacío y el camino con archivos sólo se ejercitó en el entorno B,
   contra PostgreSQL 16.
6. **R-24 sigue marcada LATENTE**, contra lo que dice el `## Outcome` de esta tarea. No
   existe ningún borde todavía y su biblioteca de validación en runtime es una dependencia
   nueva que el `## Non-scope` prohíbe instalar acá. Es una divergencia deliberada entre
   el texto de la tarea y lo implementado, y está anotada en `## Notes`.
7. **Nadie revisó esto de forma independiente.** Lo verificado acá lo verificó el mismo
   agente que lo escribió, salvo las corridas del entorno C, que ejecutó el owner sobre
   comandos que el agente redactó. No es una revisión del diff. → R-30, T-0009
