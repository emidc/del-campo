# Evidencia D-0056 — verificación en sesión real

Fecha: 2026-09-23
Claude Code: 2.1.267
Rama: task/D-0056-session-trust-bash

## Contexto

D-0056 (`decisions.yaml`) requiere, en su `falsified_by`, prueba en una sesión real: "las
denegaciones y el caso permitido deben conservar pruebas en una sesión real; la prueba
aislada no basta." Esta corrida ejecuta el `PreToolUse` de `.claude/hooks/protect-paths.mjs`
en manual mode y en auto mode, sin tocar `.claude/`, `.github/`, `decisions.yaml` ni el
propio hook.

## Pruebas — manual mode

### 1. Denegación en `.claude` (sustitución inocua)

```
sed -i '' 's/ZZZ_NO_MATCH_ZZZ/ZZZ/' .claude/settings.json
```

Decisión: **deny** del hook. Mensaje literal:

```
T-0008 / R-15: destino protegido o directorio que lo contiene. El humano aplica el cambio.
```

### 2. Denegación en `.github/workflows`

```
sed -i '' 's/ZZZ_NO_MATCH_ZZZ/ZZZ/' .github/workflows/project-os-check.yml
```

Decisión: **deny** del hook. Mismo mensaje literal que la prueba 1.

### 3. Comando compuesto que menciona una ruta protegida

```
cat .claude/settings.json > /dev/null && ls
```

Decisión: **deny** del hook. Mensaje literal:

```
T-0008 / R-15: comando compuesto u opaco menciona una ruta protegida; ejecutar la modificación desde revisión humana.
```

(Nota operativa: durante esta sesión, cualquier comando propio que mencionara `.claude` o
`.github/workflows` como argumento —incluso `git diff -- .claude` o `md5 .claude/...`,
que solo leen— también recibió deny. El hook no distingue lectura de escritura para esta
regla de "comando compuesto u opaco"; es el comportamiento documentado del hook, no algo
verificado como bug de esta prueba.)

### 4. Escritura permitida fuera de rutas protegidas

```
TASKS/_d0056-probe.md creado con "before"
sed -i '' 's/before/after/' TASKS/_d0056-probe.md
```

Decisión: el hook no emitió deny (defer); el comando corrió. Contenido verificado como
`after`. Archivo borrado después (`rm TASKS/_d0056-probe.md`).

### 5. Comando opaco (`pnpm check`)

```
pnpm check
```

Decisión: el hook no emitió deny (defer sobre `pnpm`, no reconocido). El comando corrió
completo (56 tests de `check-docs`/hook + typecheck + lint + test de `packages/`, todo en
verde). El owner confirmó en vivo que apareció el prompt normal de Claude Code para el
comando, con la opción de no volver a preguntar — es decir, el hook no forzó "ask": dejó
la decisión al flujo normal de permisos, tal como exige el statement de D-0056.

## Repetición — pruebas 1 a 5 en manual mode (segunda corrida, a pedido del owner)

El owner pidió repetir las pruebas 1 a 5 estando explícitamente en manual mode. Resultado
idéntico al de la primera corrida: pruebas 1, 2 y 3 con el mismo deny y mismo mensaje
literal; prueba 4 con escritura permitida y contenido `after` confirmado, archivo
borrado; prueba 5 (`pnpm check`) corrió completa y el owner confirmó otra vez el prompt
normal de Claude Code con "don't ask again".

## Pruebas — auto mode

El owner cambió la sesión a auto mode con Shift+Tab y lo confirmó explícitamente antes de
continuar.

### 6. `pnpm check` y `git status` en auto mode

Ambos comandos corrieron sin que el hook emitiera deny ni ask (defer en ambos casos, ya
que ninguno toca `.claude` ni `.github/workflows`); el modo auto decidió vía su
clasificador de permisos, consistente con el statement de D-0056 ("auto usa el
clasificador"). `pnpm check` volvió a pasar completo. `git status` mostró el árbol de
trabajo limpio salvo `data/` y `ops/runs/2026-09-23.jsonl`, preexistentes a esta sesión.

### 7. Repetición de la prueba 1 en auto mode

```
sed -i '' 's/ZZZ_NO_MATCH_ZZZ/ZZZ/' .claude/settings.json
```

Decisión: **deny** del hook, mismo mensaje literal que en manual mode. Confirma que la
denegación de rutas protegidas aplica en todos los modos, tal como exige el statement
("esas denegaciones aplican en todos los modos").

## Verificación de estado final

`git status --short` al cierre de la sesión:

```
?? data/
?? ops/runs/2026-09-23.jsonl
```

Ninguna de las dos entradas corresponde a `.claude/` ni `.github/workflows/`; son
preexistentes a esta sesión de verificación (no generadas por las pruebas). No hay
modificaciones registradas en archivos versionados bajo `.claude/` ni `.github/`, y no
quedó ningún archivo de prueba (`TASKS/_d0056-probe.md` fue creado y borrado en la prueba
4, repetida dos veces).

## Lo que esta corrida NO verificó

- **Hardlinks (caso `ask`).** No se ejecutó en esta sesión real el escenario de "ask"
  forzado por un archivo con hardlinks (`.claude/hooks/protect-paths.mjs`, función `ask()`,
  invocada en `evaluate` cuando `statSync(actual).nlink > 1`). Ese caso solo está cubierto
  por las pruebas unitarias de `scripts/tests/protect-paths.test.mjs`
  ("hardlinks piden revisión incluso en auto o bypass..."), no por una sesión real. No se
  probó porque el owner no lo pidió explícitamente en esta corrida.
- **bypassPermissions.** El statement de D-0056 describe el comportamiento esperado en
  `bypassPermissions` ("bypassPermissions ejecuta"), pero esta sesión no se ejecutó en ese
  modo; solo se cubrieron manual y auto.
- **`pnpm typecheck`, `pnpm lint` y `pnpm test`** se corrieron como parte de `pnpm check`
  (prueba 5), no de forma aislada, y sin volver a listarlos por separado en este documento.
- **Symlinks y traversal explícito contra rutas protegidas** en sesión real: cubiertos por
  las pruebas unitarias, no repetidos acá.

## Conclusión

D-0056 queda **respaldada** por esta corrida: las tres denegaciones (rutas protegidas en
`.claude`, en `.github/workflows`, y comando compuesto que menciona una ruta protegida)
se sostuvieron en manual mode (dos veces) y una de ellas —la denegación directa— también
en auto mode. La escritura fuera de rutas protegidas se ejecutó sin intervención del hook.
El comando opaco (`pnpm check`) no recibió `ask` forzado del hook: quedó en manos del
flujo normal de permisos y del modo de sesión, confirmado en vivo por el owner tanto en
manual como en auto mode. Ningún archivo protegido cambió durante la sesión.

El caso de `ask` por hardlinks no se verificó en sesión real en esta corrida; sigue
respaldado solo por prueba unitaria hasta que se pida esa verificación explícitamente.
